## Independent fixture and expected values

Use User A, User B with separate financial accounts and one Administrator. Keep synthetic credentials private or generated by safe local seed. Agreed THB fixture under D-03/D-04 (card purchase is a `PAYMENT` with the card as primary account; repayment is a `PAYMENT` from the bank allocated to the card):

| Action | Bank / card debt | Income / Expense |
| --- | --- | --- |
| Opening bank balance 10,000; card opening zero | 10,000 / 0 | 0 / 0 |
| Receive salary 20,000 into bank | 30,000 / 0 | 20,000 / 0 |
| Charge 1,200 to card: dining 700 + groceries 500 | 30,000 / 1,200 | 20,000 / 1,200 |
| Repay card 500 from bank | 29,500 / 700 | 20,000 / 1,200 |

These expected values are written independently. Do not call the production balance helper to compute the expected side of an assertion. Invalid allocation 700 + 400 against total 1,200 must leave the entire pre-request state unchanged. D-03 and D-04 record the agreed date, amount-limit, overpayment and insufficient-funds policies. Their payment-side boundary and atomicity tests run in Issue #21; receive-side cases remain with Issue #20. Sprint 1 has no server idempotency key: a transaction POST is not automatically retried; an ambiguous timeout requires checking history before a manual retry, and duplicate creation remains a documented limitation.

For current runs on this PR branch, the owned disposable database is `pocket_ledger_test`, created by `scripts/test-db.sh` on loopback port 55432 (PostgreSQL 18.4, tmpfs storage); the test helper refuses any other database. Earlier results below remain labelled with the PostgreSQL 18 image actually used at those commits and are historical; they do not prove a run on 18.4.
